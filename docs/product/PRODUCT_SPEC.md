# 产品规格

AgentHub 是一个以 IM 聊天为核心交互范式的多 Agent 协作平台。用户可以像使用聊天软件一样创建会话、发送消息，并与不同 Agent 单聊或群聊。

## 核心体验

- 用户通过新建对话进入任务上下文。
- 一个对话可以只包含一个 Agent，也可以在群聊模式中包含多个 Agent。
- 每个 Agent 都是聊天参与者，拥有身份、名称、头像与能力标签。
- 对话历史会作为上下文保留，支持多轮迭代。
- 用户可以 pin 关键消息，作为长期上下文输入 Agent。
- 用户可以回复整条历史消息，消息流展示引用摘要，Agent 上下文 replay 时保留被回复消息的摘要语义。
- Agent 回复不只包含文本，也可以包含代码块、文件、图片、网页预览卡片、Diff 卡片和部署状态卡片。

## 产品创新

- **聊天对象即 Agent**：把 Claude Code、Codex、OpenCode、内部预设 Agent 和用户自建 Agent 统一表现为 IM 联系人，用户不需要理解底层执行平台。
- **群聊式编排**：复杂任务可以在一个会话中由 Orchestrator 拆分、委派和汇总，降低多 Agent 协作的操作成本。
- **产物内联协作**：代码、Diff、文件、网页预览、计划和权限请求都能作为消息流或工作台产物出现，避免“聊天在一处、结果在另一处”的断裂。
- **上下文可控**：普通历史、回复引用、pin 长期上下文和外部 Agent context bridge 共同构成可解释的上下文链路。
- **权限即产品交互**：高风险文件、命令、网络和部署能力通过结构化审批进入聊天体验，而不是隐藏在 CLI 或日志中。

## 优先级

### P0

- 对话列表。
- 新建对话流程。
- 单 Agent 聊天。
- 基础消息流。
- 持久化上下文。

### P1

- 多 Agent 群聊。
- Orchestrator 任务拆分与结果聚合。
- 至少两个外部 Agent 适配器。
- 代码、文件、网页预览、Diff 等内联产物卡片。

### P2

- Diff 视图与一键应用。
- 版本历史。
- 对话式局部修改。
- 部署与发布流程。
- 桌面端与移动端扩展。

## 交付预期

- 产品设计文档。
- 技术文档。
- 可运行 Demo。
- AI 协作开发记录。
- 3 分钟 Demo 视频。

## 交付边界

本次交付以 P0/P1 主链路为核心：IM 会话、Runtime Run、HubServer 持久化、Orchestrator、外部 Agent 适配边界、基础产物投影和权限交互。P2 能力以架构、契约和 backlog 形式保留演进路径，不作为交付阻塞项。
