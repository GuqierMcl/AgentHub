# AgentHub 课题简报

本文档从早期根目录课题材料整理而来，只保留交付评审需要看到的原始目标、考察要点和交付物要求。当前产品范围以 `docs/product/PRODUCT_SPEC.md` 为准，技术边界以 `docs/architecture/` 与 `docs/contracts/` 为准。

## 课题背景

AgentHub 是一个以 IM 聊天为核心交互范式的多 Agent 协作平台。用户像使用飞书、微信一样创建会话、发送消息，并与不同 AI Agent 单聊或群聊。

平台同时接入 Claude Code、Codex、OpenCode 等主流 Agent 平台，通过统一适配器层屏蔽平台差异，并支持用户自建 Agent。Agent 输出不仅是文本，还包括代码 Diff、网页预览卡片、文件附件、文档、PPT、部署状态等可操作产物。

## 核心要求

### IM 聊天式交互

- 对话列表支持新建、置顶、归档、搜索和最近活跃排序。
- 单聊模式支持用户与一个 Agent 围绕明确任务持续对话。
- 群聊模式支持用户在一个会话内指定多个 Agent，由 Orchestrator 分派任务。
- 消息类型覆盖文本、代码块、图片、文件附件、网页预览、Diff 视图和部署状态。
- 消息操作覆盖回复、引用、重新生成、复制代码、一键应用 Diff 和展开预览。
- 聊天历史自动进入 Agent 上下文，关键消息可 pin 为长期上下文。

### Orchestrator 协调

- 在群聊模式下理解用户意图，将复杂任务拆解给合适的子 Agent。
- 子 Agent 完成后，由 Orchestrator 聚合产出并回到聊天流。
- 支持并行调度、失败降级和代码冲突处理的演进空间。

### 多 Agent 接入

- 通过统一适配器层接入至少两个主流 Agent 平台。
- 支持用户自建 Agent，包括 System Prompt、模型和工具集配置。
- 每个 Agent 在产品中表现为独立聊天对象，具备头像、名称和能力标签。

### 产物预览、编辑与发布

- Agent 回复中内联展示网页 iframe、文档渲染、代码、Diff、文件等产物卡片。
- 点击产物卡片可进入预览面板或编辑器。
- P2 范围包括版本历史、对话式局部修改、一键部署、预览 URL、静态站点部署、容器化部署和源码打包下载。

## 考察要点

| 维度 | 权重 | 评判重点 |
| --- | ---: | --- |
| AI 协作能力 | 30% | 是否沉淀 Spec、skill、rules 等可复用协作规范 |
| 功能完整度 | 25% | IM 核心体验、多 Agent 调度和上下文链路是否跑通 |
| 生成效果质量 | 20% | 聊天 UI、产物预览和交互体验是否稳定 |
| 代码理解度 | 15% | 答辩时能否解释架构选型和核心逻辑 |
| 创新与产品感 | 10% | 是否有超预期能力、产品细节和清晰设计方案 |
